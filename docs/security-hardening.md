## ⚠️ يحتاج قرار / خطوة يدوية

### #5 — قواعد Firebase (الأهم — خطوة نشر يدوية)
العميل يطلب `…/licenses/<machineHash>.json` **بدون مصادقة** (GET فقط، على مفتاح محدد —
لا يكتب ولا يسرد `/licenses.json`). المخاطر لو القواعد مفتوحة:
1. **كتابة مفتوحة** → مهاجم يكتب `status:"blocked"` ويعطّل أي جهاز عن بُعد (DoS). ← الأخطر.
2. **قراءة مفتوحة للجذر** → سرد كل الأجهزة/التراخيص (كشف معلومات).

**الحل الجاهز:** ملف `database.rules.json` في جذر المشروع — جرّبناه مع العميل الحالي
ولا يكسر أي شيء (القراءة على مفتاح محدد تشتغل، وكل كتابات العميل مرفوضة):

```json
{
  "rules": {
    "licenses": {
      ".read": false,           // يمنع سرد كل التراخيص
      ".write": false,          // يمنع الحجب عن بُعد (DoS)
      "$machineKey": {
        ".read": true,          // العميل يقرأ سجله بالمفتاح المحدد فقط
        ".write": false
      }
    }
  }
}
```

**النشر (اختَر واحدة):**
- **الأسهل — الكونسول:** Firebase Console → Realtime Database → تبويب **Rules** → الصق محتوى
  `database.rules.json` → **Publish**.
- **CLI:** `firebase deploy --only database` (يتطلب `firebase.json` يشير إلى `database.rules.json`).

**إدارة الحجب بعد التأمين:** بما أن كتابة العميل ممنوعة، اضبط `status` من:
- **Firebase Console** أو **Admin SDK** (يتجاوزان القواعد) — الأنسب. ✅ يعمل مع القواعد أعلاه.
- لو عندك **لوحة تحكم ويب** تكتب مباشرة: بدّل `".write": false` عند `$machineKey` بـ
  `".write": "auth != null"` وخلّي اللوحة تسجّل دخول بـ Firebase Auth.

**أقوى (لاحقاً):** حوّل فحص الحجب إلى Cloud Function مع توكن، بدل قراءة مباشرة غير مصادَقة —
يقفل كشف السجل الواحد أيضاً. غير عاجل.

### #1 — مفتاح تشفير النسخ الاحتياطي ثابت (مقايضة تصميم)
`getBackupKey()` مشتق من ثابت `APP_SALT` → موحّد لكل العملاء. لا يمكن ربطه بالجهاز
لأن ذلك يكسر الاستعادة على جهاز آخر (وهو الغرض الأساسي من النسخة عند تلف الجهاز)،
ولا يمكن طلب كلمة سر في النسخ التلقائية (عند الإغلاق/المجدولة) لأنها صامتة.
- **التخفيف التشغيلي الآن:** احفظ مجلد النسخ في مكان بصلاحيات وصول محدودة (مش شير مفتوح).
- **التحسين المقترح (ميزة مستقبلية):** كلمة سر اختيارية على "تصدير نسخة يدوي" فقط
  (envelope v2 بـ scrypt) للنسخ اللي بتتخزن خارج الشركة/سحابياً. النسخ التلقائية تبقى كما هي.
  ملاحظة: الـ password hashes مستبعدة أصلاً من النسخة (redaction) — لا تُسرّب كلمات مرور.

### #4 — الصلاحيات التفصيلية مطبّقة في الواجهة فقط
`canMutateRendererStorage` تسمح لأي جلسة موظف بالكتابة على كل المفاتيح (ماعدا `users`).
الفرض على مستوى الـ IPC لكل مفتاح **غير متوافق** مع بنية الكتابة المجمّعة (batched writes):
عملية واحدة (إنشاء فاتورة) تكتب دفعة واحدة على salesInvoices + products + customers +
cashbox + auditLogs… ورفض أي مفتاح يسبب كتابة جزئية = فساد بيانات.
- **الحماية الفعلية الحالية:** لا devTools في الإنتاج + CSP صارم + contextIsolation + sandbox،
  فتنفيذ JS عشوائي في الـ renderer شبه مستحيل بدون XSS.
- **الإصلاح الصحيح (إعادة هيكلة):** تغليف كل عملية منطقية في IPC handler مخصص يفرض الصلاحية
  في الـ main، بدل كتابة مفاتيح خام من الـ renderer. مشروع منفصل.

### #6 — مفتاح قاعدة البيانات مربوط بالجهاز لا بسر المستخدم
`getDbKey()` مشتق من MachineGuid (غير سري محلياً) + `APP_SALT`. يحمي من نسخ ملف القاعدة
لجهاز آخر، لكن مهاجم محلي عنده الـ binary يقدر يشتق المفتاح. مقبول لتطبيق LOB.
- **تحسين اختياري:** master password للمالك يدخل في اشتقاق المفتاح (يغيّر تجربة الإقلاع).

### #7 — التحقق من سلامة asar معطّل
`enableEmbeddedAsarIntegrityValidation: false` مقصود بسبب باگ في electron-builder v26 +
Electron 39 (موثّق في `scripts/sign-win.cjs`) يسبب كراش عند الإقلاع لو مفعّل. **لا تعيد تفعيله**
حالياً. تابع تحديثات electron-builder؛ عند إصلاح الباگ أعِد تفعيله ليُكتشف أي تلاعب بكود app.asar.

### #8 — شهادة self-signed + توقيع بدون timestamp
تحذيرات SmartScreen "ناشر غير معروف"، وكل التواقيع تبطل لحظة انتهاء الشهادة (2029).
- **✅ تم (نصف الحل):** `scripts/sign-win.cjs` بقى **يجرّب خوادم timestamp تلقائياً** (DigiCert/
  Sectigo/Certum/Starfield) ويرجع للتوقيع بدون timestamp فقط لو كلها مش متاحة. فلو ماكينة البناء
  (GitHub Actions مثلاً) عندها إنترنت → التواقيع هتصمد بعد انتهاء الشهادة.
- **متبقّي (قرار شراء):** شهادة OV/EV من CA معتمد بدل الـ self-signed لإزالة تحذير SmartScreen.

### #9 — `grantFileProtocolExtraPrivileges: true`
يوسّع صلاحيات `file://` في الإنتاج. تعطيله يقوّي العزل لكنه **قد يكسر تحميل الأصول المحلية**؛
يحتاج اختبار على بناء ويندوز فعلي قبل التغيير. اختبره على artifact قبل ما تعتمده.
