# خطة AutoParts Inventory & Sales System

## الهدف

بناء نسخة Windows مستقلة لمحلات وتجار قطع غيار السيارات، سريعة في البيع
والاستلام والجرد، وتحافظ على رقم القطعة وOEM والتوافق مع السيارة داخل كل دورة
العمل: المنتج، المخزون، الفاتورة، المرتجع، والبحث.

## حدود النسخة المستقلة

- App ID: `com.helperstechnologies.autoparts`.
- تخزين: `autoparts_inventory_v1::` وقاعدة `autoparts-inventory.secure.sqlite`.
- أكواد الأجهزة: `APW`، التفعيل: `APLIC`، الدعم: `APSUP`.
- أداة مفاتيح منفصلة في `../autoparts-license-studio` ومفتاح Ed25519 جديد.
- لا تشارك بيانات العميل أو السيريالات مع نظام المخازن العام.

## نموذج البيانات

| الكيان | البيانات الأساسية |
| --- | --- |
| VehicleMake | الاسم العربي/الإنجليزي، الشعار، البلد، المصدر، الحالة |
| VehicleModel | الماركة، الاسم، نوع المركبة، مصدر السجل |
| VehicleGeneration | الموديل، اسم/كود الجيل، من/إلى سنة، شكل الهيكل |
| VehicleEngine | الجيل، الاسم والكود، السعة، الوقود، القدرة |
| Product | Part Number، OEM[]، الماركة، المصنع، المنشأ، الجودة، الحالة، الاتجاه، موقع الرف، الضمان وإعادة الطلب |
| ProductFitment | القطعة + ماركة/موديل/جيل/محرك + مدى السنوات + ملاحظات |
| ProductAlternative | القطعة البديلة ونوعها: مكافئ، اقتصادي، أعلى جودة، أو رقم محدث |

الحقول الجديدة اختيارية عند قراءة البيانات القديمة. الترحيل يملأ Part Number
بالباركود أو الكود الداخلي عند غيابه، ويحوّل OEM إلى مصفوفة سليمة.

## كتالوج السيارات

- 387 ماركة و387 شعار PNG محلي للعمل بدون إنترنت.
- 3,781 موديل: بيانات vPIC الرسمية مع إضافات إقليمية لمصر/MENA.
- تصنيف سوق المنشأ يغطي 386 ماركة، ويعامل MG ضمن السوق الصيني الحديث (SAIC).
- زر «تخصص المحل» يسمح بكل الماركات، أو مجموعة دول مثل صيني/كوري/ألماني، أو ماركات محددة فقط، أو الجمع بين دولة وماركات استثنائية.
- التخصص يفلتر كتالوج السيارات وPart Finder وقائمة ربط القطعة، ولا يحذف أي بيانات أو توافقات قديمة.
- المستخدم يستطيع إضافة ماركة أو موديل أو جيل أو محرك وتصحيح البيانات محليًا.
- بيانات التوافق مرجع مساعد وليست بديلاً للتحقق من VIN أو كتالوج المصنع.
- أمر التحديث القابل للتكرار: `npm run catalog:sync`.

## مصفوفة الاسكان

| الشاشة | عند المسح | النجاح | الفشل |
| --- | --- | --- | --- |
| POS | Barcode ثم Part Number ثم OEM ثم الكود الداخلي | إضافة القطعة أو زيادة الكمية مع فحص المتاح | رسالة واضحة وتفريغ الحقل |
| فاتورة شراء | نفس ترتيب البحث | إضافة/زيادة سطر الاستلام | منع سجل مجهول |
| فاتورة بيع | نفس ترتيب البحث | إضافة/زيادة السطر | منع سجل مجهول |
| إضافة منتج | التقاط باركود العبوة | تعبئة الباركود | إظهار المنتج المكرر قبل الحفظ |
| المخزون | البحث الموحد | فتح حركة استلام بكمية 1 وسبب جاهز وإظهار الرف | لا تعديل بدون صلاحية |
| الجرد | البحث الموحد | كل مسحة تزيد المعدود بوحدة داخل المسودة | رفض قطعة خارج الجردة |

أجهزة USB keyboard-wedge مدعومة بلاحقة Enter أو Tab، مع عمل الإدخال اليدوي بنفس
الطريقة.

## مراحل التنفيذ

1. **الاستقلال والهوية:** مجلدان مستقلان، App ID وتخزين وترخيص وأسماء بناء جديدة.
2. **نموذج قطع الغيار:** الحقول المتخصصة، التوافق، البدائل، الترحيل والنسخ الاحتياطي.
3. **كتالوج السيارات:** الشعارات والماركات والموديلات والإدارة المحلية.
4. **دليل القطع:** بحث السيارة والسنوات والمحرك مع البحث برقم القطعة وOEM.
5. **الاسكان:** POS والمبيعات والمشتريات وإضافة المنتج والاستلام والجرد.
6. **الفواتير والضمان:** Snapshot لرقم القطعة والماركة والضمان وقت البيع والطباعة.
7. **الاستيراد والتقارير:** قالب CSV متخصص، فحص التكرار، اقتراح إعادة الطلب، وجودة بيانات التوافق والرفوف.
8. **التحقق والتسليم:** unit/integration tests، build إنتاجي، إشعارات المصادر ودليل التشغيل.

## قواعد القبول

- البحث عن `W-68/3` يجد `W 68/3` بدون حساسية للفواصل أو حالة الأحرف.
- رقم OEM واحد يجد القطعة حتى لو الباركود غير موجود.
- لا يمكن حفظ/استيراد Barcode أو Part Number مكرر بلا تنبيه.
- كل ماركة مشحونة لها شعار محلي، وكل موديل يشير لماركة موجودة.
- اختيار تخصص كوري فقط يخفي الماركات الأخرى من مسارات الاختيار مع بقاء بياناتها محفوظة.
- يمكن إضافة ماركة أمريكية منفردة إلى تخصص كوري بدون إظهار كل الماركات الأمريكية.
- ربط القطعة يُحفظ في النسخة الاحتياطية ويعود بعد الاستعادة.
- الجرد السريع لا يغير المخزون قبل اعتماد الجردة.
- الفاتورة تحتفظ برقم القطعة والماركة والضمان حتى لو تغير المنتج لاحقًا.
- `npm run build` و`npm test` ينجحان قبل إنشاء مثبت Windows.
